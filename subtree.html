Git subtree with TPLs

Quinoa uses git subtree to work with third-party libraries (TPLs). This allows easy update to their new version, records all TPL's history (including branches and tags), easily allows contributing upstream, and makes it easy to quickly try out development features of a TPL. In addition, only those developers need to learn git subtree who expect to contribute to TPLs upstream.

This page explains how to use git subtree to work with TPLs. This setup is only required

  • if you expect to make changes to TPLs (located in <quinoa>/tpl/src) and want to push those changes upstream to the TPL, or
  • if you want to update a TPL to a new version.

Otherwise you do not need this setup.

Create remote tracking branches pointing to TPLs used via git subtree

These remote tracking branches are not strictly required to use git subtree, but make life easier.

1 $ git remote add --tags -f charm http://charm.cs.uiuc.edu/gerrit/charm
2 $ git remote add --tags -f pegtl git@github.com:jbakosi/PEGTL-0.32.git
3 $ git remote add --tags -f tut git@github.com:mrzechonek/tut-framework.git
4 $ git remote add --tags -f boost git@github.com:jbakosi/Boost.git
5 $ git remote add --tags -f cartesian_product git@github.com:jbakosi/BoostMPLCartesianProduct.git
6 $ git remote add --tags -f pstreams git://git.code.sf.net/p/pstreams/code
7 $ git remote add --tags -f hdf5 git@github.com:jbakosi/HDF5.git
8 $ git remote add --tags -f netcdf git@github.com:Unidata/netcdf-c.git
9 $ git remote add --tags -f trilinos git@github.com:trilinos/trilinos.git
10 $ git remote add --tags -f hypre git@github.com:jbakosi/HYPRE.git
11 $ git remote add --tags -f rngsse2 git@github.com:jbakosi/RNGSSE2.git
12 $ git remote add --tags -f testu01 git@github.com:jbakosi/TestU01-threadsafe.git

Git subtree commands to initially merge in a set of commits (squashed) from the TPLs

The TPL commit up to which the merge is applied is given by a (remote, i.e., the TPL's) branch name, tag, or commit id. Note that these commands have already been issued to initially merge in the subtrees. Even if you expect to push updates to TPLs, you do not need to run these commands, as these merges have already been applied. They are only here for documentation of what and how it has been done to set up the subtrees.

1 $ git subtree add --prefix=tpl/src/charm charm v6.6.0 --squash
2 $ git subtree add --prefix=tpl/src/pegtl pegtl master --squash
3 $ git subtree add --prefix=tpl/src/tut tut 2013-12-18 --squash
4 $ git subtree add --prefix=tpl/src/boost boost master --squash
5 $ git subtree add --prefix=tpl/src/cartesian_product cartesian_product master --squash
6 $ git subtree add --prefix=tpl/src/pstreams pstreams RELEASE_0_8_1 --squash
7 $ git subtree add --prefix=tpl/src/hdf5 hdf5 master --squash
8 $ git subtree add --prefix=tpl/src/netcdf netcdf v4.3.2 --squash
9 $ git subtree add --prefix=tpl/src/trilinos trilinos trilinos-release-11-6-1 --squash
10 $ git subtree add --prefix=tpl/src/hypre hypre master --squash
11 $ git subtree add --prefix=tpl/src/rngsse2 rngsse2 master --squash
12 $ git subtree add --prefix=tpl/src/testu01 testu01 master --squash

Example git command to pull the latest changes to TPL charm

This is how a TPL is updated to a newer version using git subtree. Here we upgrade Charm++ from v6.6.0 to v6.6.1.

1 git fetch charm
2 git subtree pull --prefix=tpl/src/charm charm v6.6.1 --squash

Example git command to push changes to TPL testu01 via git subtree

If you have committed changes to any of the TPLs in your local clone (located in <quinoa>/tpl/src), then here is an example of how those updates can be pushed upstream.

First, verify the changes you are about to push by examining the diff output:

$ git diff testu01/master master:tpl/src/testu01

If you are happy with the diff, push the changes to the TPL:

$ git subtree push --prefix=tpl/src/testu01 testu01 master
