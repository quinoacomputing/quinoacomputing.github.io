12  Advanced Array Creation. This class does a distribution that is based on
13  which portion of a distributed sparse matrix resulting from discretization
14  on an unstructured grid residing on a PE should hold a given chare array
15  element. (The one that owns most on-PE rows to minimize off-PE
16  communication.)
17 
18  Note that to help with performance, it is not advised to do heavy
19  computations in the overridden member functions, procNum() and
20  populateInitial(), since they can be potentially called many times. See
21  also this note on the inner workings of the Charm++ runtime system
22  regarding map objects and array element creation from long-time Charm++
23  developer, Eric Bohm, also at:
24  http://lists.cs.uiuc.edu/pipermail/charm/2015-May/002047.html
25 
26  _Procnum will be called to construct your chare, the first time a message
27  is sent to it from a node, and each time subsequent sends do not find a
28  precached location record for it. The latter event can occur when many
29  sends have pushed it out of cache, or after migration._
30 
31  _The potential global memory footprint of location management caching is
32  proportional to the total number of objects multiplied by the number of
33  nodes. Therefore, the runtime system keeps a finite number on each node.
34  At the limit, procnum could be called for nearly every message send,
35  therefore procnum should be designed to be inexpensive._
36 
37  The heavy portion of array element placement should therefore be done in
38  the constructor.
39 */
