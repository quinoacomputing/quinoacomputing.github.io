61  //! \brief Constructor: set all defaults.
62  //! \param[in] ctrinfo std::map of control file keywords and their info
63  //! \details Anything not set here is initialized by the compiler using the
64  //! default constructor for the corresponding type. The ctrinfo map
65  //! argument is optional. If not given, it is an empty std::map
66  //! constructed in-place and affects nothing. If given, it contains the
67  //! control file keywords, all of which are moved into the relevant slot
68  //! (tag::ctrinfo). This allows constructing, e.g., a CmdLine object both
69  //! with and without this information in place, which are both used at
70  //! different stages of the execution. For example, because the
71  //! command-line is parsed very early on during runtime while the input
72  //! deck is only parsed much later, the control-file keywords and their
73  //! information (owned by and generated by the input deck and its
74  //! constructor) is not yet available when the CmdLine object is
75  //! constructed. However, during command-line parsing it is still possible
76  //! to request information on a control file keyword, so it must be
77  //! available. The input deck is where all parsed information goes during
78  //! control file parsing and is stored at global scope, see, e.g.,
79  //! walker::g_inputdeck. This global-scope (still namespace-scope), input
80  //! deck object is thus created before command-line parsing. The input
81  //! deck object's constructor (working only on type information, available
82  //! at compile-time, of all the control file keywords) creates a run-time
83  //! map. This is a run-time map, but available before main() starts,
84  //! because it is const and it is initialized as a global-scope map. This
85  //! map is then passed in here as ctrinfo, and its contents inserted into
86  //! the CmdLine object, making the control-file keywords and their info
87  //! available during command-line parsing. Since the input deck stack
88  //! contains a copy of the command-line stack, the command-line stack must
89  //! be possible to be instantiated without passing the ctrinfo map,
90  //! otherwise it would be a mutual dependency.
91  //! \author J. Bakosi
92  CmdLine( tk::ctr::HelpFactory ctrinfo = tk::ctr::HelpFactory() ) {
93  set< tag::io, tag::output >( "out" );
94  set< tag::virtualization >( 0.0 );
95  set< tag::verbose >( false ); // Quiet output by default
96  // Initialize help: fill from own keywords + add map passed in
97  boost::mpl::for_each< keywords >( tk::ctr::Info( get< tag::cmdinfo >() ) );
98  get< tag::ctrinfo >() = std::move( ctrinfo );
99  }
